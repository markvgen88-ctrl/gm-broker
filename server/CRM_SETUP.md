# Настройка CRM (админ-панель /admin)

CRM — это третий, полностью независимый канал сохранения заявок (вдобавок
к Telegram и Email), плюс защищённая паролем
страница `/admin` на сайте, где можно смотреть заявки, менять их статус
и оставлять комментарии. Настройка бесплатная, база — внешний Postgres
(Neon), без привязки к Timeweb. Занимает 10–15 минут.

Пока эти переменные не заданы, сайт продолжает работать как раньше —
Telegram/Email не затронуты, просто `/admin` будет отвечать «CRM ещё
не настроена».

## Шаг 1. Создать базу в Neon

1. Зайдите на [neon.tech](https://neon.tech) → зарегистрируйтесь (можно через
   GitHub-аккаунт).
2. **Create a project** → дайте имя, например «gm-broker» → регион ближе
   к серверу (например, Frankfurt / eu-central-1).
3. На странице проекта откройте **Connection string**. Выберите вариант
   **Pooled connection** (важно — не Direct connection: пул выдерживает
   больше параллельных запросов и лучше подходит для веб-сервера).
4. Скопируйте строку вида:

   ```
   postgresql://neondb_owner:AbCdEf123@ep-example-12345-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   Она уже содержит `?sslmode=require` — это нормально и обязательно.

## Шаг 2. Сгенерировать пароль и секрет

Понадобятся два значения:

- **ADMIN_PASSWORD** — пароль для входа в `/admin`. Придумайте длинный,
  не используемый больше нигде пароль (например, сгенерируйте в менеджере
  паролей).
- **ADMIN_SESSION_SECRET** — случайная строка, которой подписывается кука
  сессии. Сгенерировать в терминале:

  ```bash
  openssl rand -hex 32
  ```

  Если под рукой нет терминала с `openssl` — подойдёт любая случайная строка
  из 40+ символов (например, тоже из менеджера паролей).

## Шаг 3. Прописать переменные на сервере

В `.env` на сервере (Timeweb → настройки приложения → переменные окружения)
добавьте:

```
DATABASE_URL=postgresql://neondb_owner:AbCdEf123@ep-example-12345-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
ADMIN_PASSWORD=<придуманный пароль>
ADMIN_SESSION_SECRET=<строка из шага 2>
```

## Шаг 4. Установить новые зависимости и задеплоить

В `server/package.json` добавились три пакета (`pg`, `jsonwebtoken`,
`cookie-parser`). Если деплоите через тот же процесс, что и раньше
(GitHub → Timeweb автосборка), Timeweb сам выполнит `npm install` при
пересборке — отдельно ничего ставить не нужно. Для локальной разработки:

```bash
cd server
npm install
```

Таблицы в базе (`applications`, `application_comments`) создаются
автоматически при первом запуске сервера — отдельного шага миграции нет.
В логах при старте должна появиться строка:

```
[db] Схема CRM проверена/создана.
```

## Шаг 5. Проверка

1. Откройте `https://gm-broker.ru/admin` → должна открыться страница входа.
2. Введите `ADMIN_PASSWORD` → должен открыться пустой список заявок.
3. Пройдите анкету на самом сайте до конца (укажите тестовые имя/телефон/
   e-mail) → заявка должна появиться в `/admin` в течение пары секунд после
   отправки, со статусом «Новая заявка».
4. Откройте заявку → смените статус, добавьте тестовый комментарий →
   обновите страницу — изменения должны сохраниться.

Если заявка не появилась в `/admin`, но пришла в Telegram/на почту — в логах
сервера будет строка вида:

```
[submit] crm delivery failed: ...
```

Это не мешает работе сайта (заявка всё равно дошла по остальным каналам), но
стоит проверить `DATABASE_URL` — скорее всего, опечатка в строке подключения
или не тот вариант («Direct» вместо «Pooled»).

## На будущее

- Пароль один на весь `/admin` — если понадобится доступ ещё кому-то, сейчас
  для этого нет отдельного механизма (все видят и меняют одни и те же
  заявки под одним и тем же входом). Дайте знать, если понадобится
  несколько аккаунтов — это отдельная, не очень большая доработка.
- Список статусов воронки (Новая заявка → В работе → … → Сделка закрыта)
  зашит в коде в двух местах: `server/src/lib/statuses.ts` (проверка на
  сервере) и `client/src/data/adminStatuses.ts` (подписи и цвета на
  клиенте). Если нужно добавить/переименовать этап — присылайте, обновлю
  оба файла.
